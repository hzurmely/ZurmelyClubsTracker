# Packaging the desktop program

What lives here is the Electron shell: a window that starts the site itself on a
local server and points at it. The site goes into the `site/` folder, which is
generated by the build and therefore not versioned. The binary icons are not
versioned either, and the recipe below generates both.

## The recipe

```bash
# 1. Next build in standalone mode
#    Check first that .env.local does NOT have EA_DEMO=1, otherwise the fake
#    data ends up inside the executable.
cd ..
rm -rf .next desktop/site
BUILD_DESKTOP=1 npm run build

# 2. copy the build into the shell
cp -r .next/standalone desktop/site
mkdir -p desktop/site/.next
cp -r .next/static desktop/site/.next/static
cp -r public desktop/site/public 2>/dev/null || true

# 3. generate the icons from app/icon.svg
pip install cairosvg pillow --break-system-packages
python3 - <<'END'
import cairosvg
from PIL import Image
cairosvg.svg2png(url='app/icon.svg', write_to='desktop/icone.png',
                 output_width=512, output_height=512)
cairosvg.svg2png(url='app/icon.svg', write_to='/tmp/i256.png',
                 output_width=256, output_height=256)
Image.open('/tmp/i256.png').convert('RGBA').save(
    'desktop/icone.ico', format='ICO',
    sizes=[(16,16),(24,24),(32,32),(48,48),(64,64),(128,128),(256,256)])
END

# 4. package (runs on Linux, Mac or Windows)
npm install -g @electron/packager
npx electron-packager desktop ZurmelyClubsTracker \
  --platform=win32 --arch=x64 --out=dist --overwrite \
  --electron-version=38.4.0 --icon=desktop/icone.ico \
  --prune=false --asar=false

# 5. drop the locales nobody uses (about 40 MB saved)
cd dist/ZurmelyClubsTracker-win32-x64/locales
ls | grep -vE '^(en-US|pt-BR|pt-PT)\.pak$' | xargs rm -f
```

The result lands in `dist/ZurmelyClubsTracker-win32-x64`, with the `.exe` at the
root.

To target another system, change `--platform` to `darwin` or `linux`.

## Checking it before sending it to anyone

The packaged server can be started without opening Electron, and that is how you
find a broken build without being on Windows:

```bash
EA_DEMO=1 PORT=4050 node desktop/site/server.js
```

Then open the routes and check they all answer 200:

```
/
/clube/common-gen5/1001
/clube/common-gen5/1001/jogador/Maestro10
/clube/common-gen5/1001/partida/demo-0
/comparar
/sobre
```

Worth checking both languages while you are there, since the language comes from
a cookie:

```bash
curl -s -H 'Cookie: zct_lang=en' http://localhost:4050/sobre | grep -o '<h3[^>]*>[^<]*' | head -3
curl -s -H 'Cookie: zct_lang=pt' http://localhost:4050/sobre | grep -o '<h3[^>]*>[^<]*' | head -3
```

## Details that matter

`main.js` starts the server with `process.execPath` and `ELECTRON_RUN_AS_NODE=1`,
meaning the Electron executable itself plays the part of Node. That is why the
program does not require Node installed on the machine running it.

The port is drawn from the free ones on every launch, so it never fights with
other programs.

`--asar=false` is mandatory: with asar on, `server.js` ends up inside a packed
archive and the child process cannot read it. The packager warns with "asar
parameter set to an invalid value (false), ignoring and disabling asar", which is
exactly what we want.

`main.js` builds its paths from `__dirname`, not `process.resourcesPath`, because
without asar the `site/` folder sits right next to it.

The application menu follows the system language: Portuguese on a Portuguese
system, English everywhere else, matching how the site follows the browser.

`main.js` passes `ZCT_DATA_DIR` to the server process, pointing at
`Documents/ZurmelyClubsTracker/historico`. That variable is the only thing that
turns the match archive on, so a build without it behaves exactly like the
published site. To test the archive by hand, start the packaged server with the
variable set:

```bash
EA_DEMO=1 ZCT_DATA_DIR=/tmp/historico PORT=4050 node desktop/site/server.js
```

Note that demo mode does not write to the archive on purpose, so that fake data
never lands in a real folder.

## Why the program beats the published site

EA blocks datacenter IP ranges. Running on a home machine, the request leaves
from a residential IP and EA answers directly, with no need for the `r.jina.ai`
reader detour that `lib/ea.js` uses when it is in the cloud. In practice that
means faster pages and no dependency on a third party service.

## Delivering it

The package is over 300 MB and the zip lands near 130 MB, above the limit of
several transfer channels. What worked here was slicing the zip into 19 MB parts
and shipping an `INSTALAR.bat` alongside that joins them with `copy /b`, extracts
with PowerShell `Expand-Archive` and creates the desktop shortcut.

Windows Defender usually warns about an unknown executable on first launch,
because the package is not signed. That is expected.
